# FALCON ReID — backend и ML

Бэкенд сервиса FALCON ReID: FastAPI-сервис (`service/`) и ML-часть (`src/`) —
обучение, продовый экстрактор признака, метрики, артефакты сдачи, бенчмарки.
Запуск всего решения одной командой, требования, API и список внешних ресурсов —
в [корневом README](../README.md). Сопроводительная документация —
[`docs/SOLUTION.md`](../docs/SOLUTION.md), журнал всех экспериментов —
[`docs/PROGRESS.md`](../docs/PROGRESS.md).

## Что внутри

| Путь | Описание |
|---|---|
| `src/` | обучение, инференс (`extractor.py`), метрики постановщика, порог, артефакты сдачи, бенчмарки |
| `service/` | FastAPI: `routers/` (HTTP), `services/` (бизнес-логика), `schemas/` (Pydantic), `auth.py` (JWT / API-ключи), `db.py` + `models_db.py` (PostgreSQL), `reid_inference.py` (модели, torch), `gallery_index.py` (FAISS, без torch) |
| `models/` | манифест состава `ensemble.json`, порог `threshold.json`, постобработка `postproc.json`, `weights.json` (URL и sha256 весов). Сами веса — в релизе [`weights-v4`](https://github.com/Enoti4Ka44/FalconREID/releases/tag/weights-v4), скачиваются при сборке образа |
| `artifacts/` | `submission.csv`, `embeddings.npy`, `candidates.csv`, отчёты замеров, фигуры, скриншоты |
| [`../docs/`](../docs) (корень репозитория) | SOLUTION.md, PROGRESS.md, PITCH.md (речь защиты), презентация и её сборщик `deck_v4.py` |
| `mcp_server.py`, `MCP_guide.md` | необязательная интеграция API с AI-агентами по MCP (`pip install mcp httpx`) |

## Запуск без Docker

```bash
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu126
python -m src.fetch_weights                     # веса из релиза, с проверкой sha256
python -m src.run_all --data-root /путь/к/датасету --out-dir artifacts
python -m src.validate_submission --data-root /путь/к/датасету --artifacts artifacts
```

Сервис локально (нужен PostgreSQL, например `docker compose up -d postgres` из
корня, добавив ему `ports: ["5432:5432"]`, либо свой):

```bash
export DATABASE_URL=postgresql+asyncpg://falcon:falcon@localhost:5432/falcon
export GALLERY_INDEX=models/gallery_index.npz
export DATA_ROOT=/путь/к/датасету
uvicorn service.app:app --host 0.0.0.0 --port 8000
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATA_ROOT` | `/data` | каталог с `images/`, `crops/`, CSV |
| `GALLERY_INDEX` | `/app/models/gallery_index.npz` | индекс галереи; рядом ищутся `ensemble.json`, `threshold.json`, `postproc.json` |
| `REFUSAL_THRESHOLD` | из `models/threshold.json` (0.455) | переопределение порога отказа |
| `DATABASE_URL` | `postgresql+asyncpg://falcon:falcon@localhost:5432/falcon` | PostgreSQL |
| `JWT_SECRET` | `change-me-in-production` | секрет подписи JWT |
| `SEED_USERNAME` / `SEED_PASSWORD` | `test` / `test` | демо-пользователь, создаётся при старте |

## Архитектура решения

```
кадр JPEG + BBox ──► декодирование и кроп на CPU в пуле потоков (+6% контекста)
   ──► DINOv3 ViT-L/16 + части-признаки (256²)       ─┐
   ──► 0.7 · DINOv2 ViT-B/14 + части-признаки (252²) ─┴─► конкатенация ─► 3072-d float32
   ──► DBA k=2, α=1.0 (статичная галерея) ─► L2-нормировка
   ──► косинусный поиск FAISS ─► топ-10 | отказ (max sim < τ)
```

* **Две модели** (`models/ensemble.json`): DINOv3 ViT-L/16 на входе 256² с
  части-признаками (303M) + 0.7·ViT-B/14 DINOv2 с части-признаками (87M).
  Партнёр выбран не по силе, а по **декоррелированности**: другая
  предобучающая выборка (DINOv2 LVD-142M против DINOv3 LVD-1689M).
  Веса в fp16: **755 МиБ** + индекс галереи 8.8 МиБ + детектор 6.2 МиБ = 770 МиБ, лимит 2048.
* **Почему не самая точная модель.** DINOv3 ViT-H+ (841M) в паре даёт
  mAP@10 0.883 против 0.859, но по протоколу стенда упирается в 68 FPS —
  12.4 очка скорости из 20 против полных 20 у выбранной пары.
  Разница по качеству стоит около 1.1 очка из 45, по скорости — около 7.6
  из 20. ViT-H+ обучен и лежит в архиве, откат занимает около часа.
* **Обучение (каждая модель):** классификация идентичностей с отступом
  CosFace (s=48, m=0.25) + batch-hard triplet (m=0.3), BNNeck,
  память по батчам **XBM** (4096 признаков прошлых батчей как трудные
  негативы, +0.0077 mAP@10),
  PK-сэмплирование, AdamW + косинусный LR с прогревом, AMP.
  Аугментации: **Pad+RandomCrop** (сдвиг 5% — учит устойчивости к неточной
  рамке детектора, даёт +3 mAP), flip, color jitter, blur, random erasing.
* **Инференс** (`src/extractor.py`) — один и тот же код строит
  `embeddings.npy` и меряется на скорость. Полный кадр декодируется на CPU в пуле потоков, пока GPU считает предыдущую порцию,
  проход каждой сети записан в **CUDA-граф** под батчи 1/8/16/32. Без
  TTA-отражения: в паре моделей оно не даёт ничего (mAP@10 −0.0000), а время
  удваивает. Постобработка — DBA k=2 с α=1.0 по статичной галерее (+0.9 mAP).
* **Потоковый протокол** (требование постановщика): каждый запрос
  обрабатывается независимо, используются только галерея и текущий запрос;
  запросы друг о друге ничего не знают.

## Метрики

Все значения — среднее по **30 переразбиениям** отложенной валидации
(308 незнакомых модели ТС), метрики — по определениям постановщика
(`src/official_metrics.py`): mAP@10 с junk-фильтром «то же ТС + та же камера»
до усечения, режим отказа по верхнему кандидату с 20% запросов без пары,
как в закрытом тесте. Разброс при пересборке разбиения ±0.011 mAP, поэтому
одиночный замер для таких сравнений непригоден; все сравнения парные.

| Метрика | Было (4 модели) | Стало (2 модели) |
|---|---|---|
| **mAP@10** (45% итога) | 0.8268 | **0.8585** |
| Rank-1 / Rank-5 | 0.794 / 0.900 | **0.823 / 0.917** |
| mAP (полное ранжирование, справочно) | 0.8347 | **0.8638** |
| Режим отказа 0.7·F1 + 0.3·TNR (10%) | 0.681 | **0.722** |
| TNR | 0.437 | **0.701** |
| Latency, полный цикл, батч 1 | ~102 мс | **17.1 мс** |
| Лучший FPS (батчи 1/8/16/32) | ~33 | **126.3** |
| Вес файлов | 1511 МиБ | **770 МиБ** |

Скорость — по протоколу стенда (`src/bench_official.py`): чтение JPEG
1920×1080 с диска, декодирование, кроп, препроцессинг, сеть, L2; медиана 300
прогонов после 50 прогревочных, RTX 4070 Ti SUPER.

**Режим кандидатов.** Тестовая галерея содержит кадры тех же сцен, что и
запросы: у 72% запросов top-1 — кадр-дубль той же машины на той же камере.
Правило по фону кадра и геометрии BBox (`src/camera_infer.py`) отсеивает
такие дубли; его precision на train 0.97–1.0 при полноте по всем
одно-камерным парам 0.005 — то есть это **фильтр дублей**, а не
восстановление камер. Отказ кодируется отсутствием строк в `candidates.csv`.

**Абляции** (парно, 30 переразбиений; полный журнал — [`docs/PROGRESS.md`](../docs/PROGRESS.md)):

| шаг | mAP@10 / Δ |
|---|---|
| прежний четверной ансамбль, DBA3/AQE1/α=3 | 0.8268 |
| постобработка DBA2 / без AQE / α=1.0 | +0.0086 (полный mAP) |
| снятие ConvNeXt (прирост был на уровне шума) | +0.0013, −171 МиБ |
| аугментация Pad+RandomCrop, соло ViT-B | +0.0295 |
| DINOv3-L переобучен новым рецептом, соло | 0.7845 → 0.8213 |
| + части-признаки для DINOv3-L, соло | 0.8318 |
| DINOv3-L·части + 0.7·ViT-B·части | 0.8475 |
| + дистилляция от ViT-H+ (вес 1000) | 0.8508 |
| **+ память по батчам XBM 4096 в обеих моделях** | **0.8585** (+0.0077, 30/30) |

Проверено и отвергнуто с числами: обучаемый классификатор отказа,
графовая диффузия эмбеддингов, итеративный DBA/AQE, слияние на уровне
похожестей, PCA-отбеливание, потоковый k-reciprocal re-ranking (при трёх
снимках на машину в галерее даёт +0.001), многомасштабный TTA, сохранение
пропорций кропа, SigLIP/ViT-g/ConvNeXt·DINOv3 как участники ансамбля.

## Обоснование порога отказа

Балл за режим кандидатов по формуле постановщика: `10% × (0.7·F1 + 0.3·TNR)`,
F1 и TNR — по запросам, по верхнему кандидату. Порог выбран максимизацией
этой величины на валидации с 20% запросов без пары (как в закрытом тесте):
отбор на сидах 42–61, проверка на отложенных 82–111 (`src/threshold_official.py`).
Рабочая точка: **τ = 0.455**, F1 0.731, TNR 0.701. Прежний порог 0.318
подбирался по F1 при ~50% запросов без пары и считал «ответил, но неверно»
верным ответом — на реальном составе теста он давал TNR 0.44. Оператор может
переопределить порог переменной `REFUSAL_THRESHOLD`.

## Воспроизведение обучения

```bash
python -m src.prepare_crops --data-root /данные --out /данные/crops   # кэш кропов
```

Модели для ЗАМЕРА (обучаются на 1233 ТС, 308 отложены):

```bash
python -m src.experiments --run d_ps bp_shift     # обучение + честная оценка
python -m src.eval_multiseed --add D=artifacts/cand/d_ps.npz BP=artifacts/cand/bp_shift.npz
```

Модели для СДАЧИ (на всех 1541 ТС) и сборка артефактов:

```bash
python -m src.rebuild_prod --train      # обучить продовые модели
python -m src.rebuild_prod --assemble   # манифест, порог, индекс, артефакты, бенчмарк
```

Состав, размеры входа и веса конкатенации задаются словарём `PROD`
в `src/rebuild_prod.py`; очередь экспериментов — `EXPERIMENTS`
в `src/experiments.py`.

**Про замеры.** Любое сравнение делается парно по 30 переразбиениям
протокола (`src/eval_multiseed.py`). Замер на одном разбиении для приростов
порядка 0.01 mAP непригоден: разброс самого протокола ±0.011. Подтверждением
считается |Δ| > 2·SE.

Сиды зафиксированы (`seed=42`), разбиение train/val детерминировано.

## Производительность

Замер по протоколу стенда: `python -m src.bench_official --prod` →
`artifacts/bench_official.json`. Полный цикл от чтения JPEG до вектора,
latency — медиана 300 прогонов при батче 1, FPS — лучший из батчей 1/8/16/32.

| GPU | Батч 1 | Лучший FPS | Файл |
|---|---|---|---|
| RTX 4070 Ti SUPER | 17.1 мс | 126.3 | `artifacts/bench_official.json` |
| RTX 3060 12 ГБ | 38.6 мс | 55.1 | `artifacts/bench_official_rtx3060.json` |
| RTX 3060 12 ГБ, Docker (WSL2) | 47.1 мс | 53.2 | `artifacts/bench_official_rtx3060_docker.json` |

Масштабируемость до 10⁶ галереи: `python -m src.ann_demo` (FAISS HNSW, recall@10
против точного поиска) → `artifacts/ann_demo.json`.

## Карта внимания

`POST /api/explain` строит карту внимания CLS-токена последнего блока DINOv2 ViT-B
(у DINOv3 внимание с RoPE, его ручной пересчёт некорректен). Горячие зоны — фары,
диски, рейлинги, силуэт; размытый номер модель не использует.
